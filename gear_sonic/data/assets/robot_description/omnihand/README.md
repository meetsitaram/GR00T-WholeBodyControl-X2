# OmniHand 2025 — vendored kinematic assets

Articulated 10-active-DOF dexterous hand from AgiBot, used by the X2 Ultra
embodiment for *visual* rendering only. Sourced from
[`AgibotTech/Omnihand-2025-SDK`](https://github.com/AgibotTech/Omnihand-2025-SDK)
under Mulan PSL v2 (see upstream LICENSE).

## What's here

```
omnihand/
├── README.md                          (this file)
├── omnihand_left.urdf                 (cleaned, paths fixed)
├── omnihand_right.urdf                (cleaned, paths fixed)
└── meshes/
    ├── l_palm.STL                     (left palm)
    ├── r_palm.STL                     (right palm)
    ├── l_thumb_roll.STL               (mirrored thumb base)
    ├── r_thumb_roll.STL
    ├── thumb_abad.STL                 (shared L/R: thumb spread joint)
    ├── thumb_mcp.STL                  (thumb proximal phalanx)
    ├── thumb_pip.STL                  (thumb middle phalanx, mimic-driven)
    ├── thumb_dip.STL                  (thumb distal phalanx, mimic-driven)
    ├── finger_abad.STL                (shared: finger spread base)
    ├── finger_pip.STL                 (shared: proximal phalanx)
    └── finger_dip.STL                 (shared: distal phalanx, mimic-driven)
```

11 STLs total (~9 MB). Both hands share the four generic finger meshes; the
palm and thumb-roll segments are mirrored.

## Cleanup applied vs upstream

The upstream URDFs are autogenerated from xacro and ship with three issues
that prevent direct loading by MuJoCo:

1. **Absolute mesh paths** like
   `filename="/home/hj/Desktop/aima_moduel/omnihand_description/assets/meshes/r_palm.STL"`
   were rewritten to relative paths (`filename="meshes/r_palm.STL"`).
2. **Stray `y` tokens** on their own line between the `*_abad` and `*_pip`
   joints (line~237 in the right URDF, similar in the left) — almost certainly
   leftover xacro substitution debris — were stripped. The MuJoCo URDF parser
   silently rejects this otherwise.
3. **Embedded `<mujoco>` compiler block** added immediately under `<robot>`:

   ```xml
   <mujoco>
     <compiler discardvisual="false" meshdir="meshes"/>
   </mujoco>
   ```

   MuJoCo's URDF importer defaults to `discardvisual="true"`, which silently
   drops every `<visual><mesh/>` element and only loads `<collision>`
   primitives. Without this block, the loaded model has finger bodies but
   no finger meshes — fingers literally render invisible. The
   `meshdir="meshes"` attribute pins the mesh search root to the per-package
   ``meshes/`` subdirectory regardless of which working directory the
   loader was invoked from. Other URDF consumers (RViz, Drake, Pinocchio,
   PyBullet, ros_control) ignore the block.

No joint limits, mesh transforms, mass properties, or kinematic structure
were modified.

## Joint structure (per side)

The URDFs encode **10 active + 6 passive (mimic) DOFs**, matching the SDK
README spec. Active joint order is canonical and matches
`OMNIHAND_FINGER_NAMES_PER_SIDE` in
`gear_sonic/data/robot_model/supplemental_info/x2_ultra/x2_ultra_supplemental_info.py`:

| # | Active joint     | Drives passive (mimic) joints                                |
|---|------------------|--------------------------------------------------------------|
| 1 | thumb_roll       | —                                                            |
| 2 | thumb_abad       | —                                                            |
| 3 | thumb_mcp        | thumb_pip = 1.33 × mcp,  thumb_dip = 1.30 × mcp              |
| 4 | index_abad       | —                                                            |
| 5 | index_pip        | index_dip = 1.097 × pip                                      |
| 6 | middle_pip       | middle_dip = 1.097 × pip   (middle_abad is fixed in URDF)    |
| 7 | ring_abad        | —                                                            |
| 8 | ring_pip         | ring_dip = 1.097 × pip                                       |
| 9 | pinky_abad       | —                                                            |
| 10| pinky_pip        | pinky_dip = 1.097 × pip                                      |

URDF `<mimic>` semantics are not preserved by MuJoCo's URDF→MJCF pipeline, so
the renderer composer recreates each mimic relationship at MJCF assembly time
as a `<equality joint>` constraint. See
`gear_sonic/scripts/compose_x2_with_omnihand.py` for the exact data tuples.

## Renderer-only, NOT in the training MJCF

The X2 Ultra training MJCF (`x2_ultra.xml`) deliberately ends each arm at
`*_wrist_roll_link` — 31 DOFs, matching SONIC's tracking decoder, the deploy
ONNX, and the AimDK ROS 2 HAL contract. **Hand commands flow out-of-band**
via `/aima/hal/joint/hand/command` on the real robot.

The OmniHand assets here exist purely so we can **render** what the
out-of-band hand command stream would have produced kinematically. The
augmented MJCF (`x2_ultra_with_omnihand.xml`, generated on the fly by
`compose_x2_with_omnihand.py`) is consumed only by the inspection-video
renderer and the M5 camera-plumbing pipeline, never by the trainer or
deployer.
